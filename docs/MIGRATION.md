# Переход с прошивки 1.x (`resistButtons.ino`) на 2.0

Документ для тех, кто обновляет адаптер и приложение на магнитоле (PSADisplay). Полное описание нового
протокола — в [PROTOCOL.md](PROTOCOL.md).

## Что нужно изменить в приложении (PSADisplay)

| Было (1.x) | Стало (2.0) | Что сделать |
|---|---|---|
| Порт 9600 бод | **115200 бод** | `BAUD_RATE = 115200` в `AdapterService` |
| Строка старта `Start work` | `ADAPTER PSA-CAN 2.0 FULL` (или `LITE`), за ней все `MODE` и `STATE` | `FIRMWARE_START_LINE` заменить проверкой `line.startsWith("ADAPTER ")` |
| Кнопки руля видны только в отладочном режиме (`D`): `key N was up.` / `key N was up. long` | Всегда приходят строки `KEY <имя>` / `KEY <имя> LONG`, включать ничего не нужно | `WheelKeys` разбирать по `^KEY (\w+)( LONG)?$`; команду `D` при подключении больше не слать |
| Номер кнопки N | Имя | 1 → `VOL_DOWN`, 2 → `VOL_UP`, 3 → `MUTE`, 4 → `SEEK_FWD`, 5 → `SCROLL_DOWN`, 6 → `SCROLL_UP` |
| — | Новые кнопки | `SEEK_BACK`, `SOURCE`, кнопки меню `MODE`, `MENU`, `ESC`, `OK` |
| Долгое нажатие: при отпускании, если держали ≥ 0,5 с | Так же: `KEY … LONG` при отпускании | ничего |
| Двойное срабатывание: адаптер всегда нажимал резистивную кнопку | Команда `k` отключает провод KEY, `K` включает | при включённой настройке «кнопки руля → Android» слать `k` после каждой строки `ADAPTER`; при выключенной — `K` |
| Задний ход и подсветка — только реле | Ещё и строки `STATE REVERSE ON\|OFF`, `STATE ILLUMINATION ON\|OFF` | по желанию: реагировать в приложении (в варианте LITE это единственный канал) |
| Пересылались пакеты 1A1, 220, 221 — каждый принятый | Те же и F6, B6, 128, 161, 261, 2A1 — только изменения и повтор раз в 2 с | формат строки `CAN …` прежний, `CanLineParser` менять не нужно; можно добавлять разбор новых ID в `PsaDecoder` |
| Команды `1`–`9` не доходили до шины (ошибка в `EmulateButtonsPSA::SetButton`) | Работают | убрать оговорку из документации |
| Отладочные строки произвольного вида | Все начинаются с `# `, тексты изменились | не разбирать их |

Новые строки (`KEY`, `STATE`, `MODE`, `ADAPTER`, `#`) текущий `CanLineParser` за пакеты не принимает:
первое слово не является HEX-числом до трёх знаков.

Команды обучения: `e` / `E` убраны (дублировали `t` / `T`), добавлены `b` `B` `o` `O` и `?`, `K`, `k`.

## Что изменилось в прошивке

- Скетч переехал: `resistButtons.ino` → `PsaCanAdapter/PsaCanAdapter.ino`, настройки собраны в `Config.h`.
- Два варианта сборки (`VARIANT` в `Config.h`): `VARIANT_FULL` и `VARIANT_LITE`.
- Bluetooth (HC-05) по умолчанию выключен (`USE_BLUETOOTH`): программный UART задерживал цикл.
- Убраны выходы ламп прицепа на A0–A6 и расчёт стоп-сигнала по замедлению — этим занимается отдельный
  модуль `psa-module-trailer-hitch`. Режим прицепа остался: он не даёт задней передаче включать камеру.
- Исправлено: ложное срабатывание обеих «кнопок» колёсика при переполнении счётчика и на первом пакете;
  команда `l` печатала «on».
- X9C104 управляется без записи положения в его память при каждом нажатии (ресурс памяти — 100 000 записей).
  Библиотека `DigiPotX9Cxxx` больше не нужна.

## Железо

- **Старая плата (релейный модуль, LM2596, X9C104) работает с вариантом FULL без переделок**: пины те же,
  реле по-прежнему включаются низким уровнем, сопротивления шести прежних кнопок не изменились —
  магнитолу переучивать не нужно. HC-05 можно снять.
- Новая плата FULL: реле → две оптопары PC817, LM2596 → Mini360, добавлена защита по питанию.
- Вариант LITE: только Nano и MCP2515, питание от USB; провода KEY, BACK и ILL к магнитоле не идут.

Схемы, перечень деталей и корпуса — в [hardware/README.md](../hardware/README.md).

## Библиотеки Arduino

Старые копии `CanFrameLog`, `EmulateButtonsPSA`, `EmulateBSIPSA`, `EmulateRadioPSA`, `DigiPotX9Cxxx` из
`Documents/Arduino/libraries` больше не используются. Нужны `libraries/autowp-mcp2515` и
`libraries/PsaEmulators` из этого репозитория (см. README).
